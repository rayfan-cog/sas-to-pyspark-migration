# Golden SAS outputs

The PySpark migration is only "correct" against numbers SAS actually produced. These
files are that reference set. Until they exist, the parity tests skip themselves —
never hand-write or estimate the values.

## How to generate them

1. On a machine with SAS 9.4 (or SAS Viya) and this repo's `data/home_equity.csv`
   available at the path used by `sas/01_data_loading.sas`, run the programs in order
   in a single SAS session so the `work` library carries between them:

   ```sas
   %include "sas/01_data_loading.sas";
   %include "sas/02_data_cleaning.sas";
   %include "sas/03_aggregation_reporting.sas";
   %include "sas/04_risk_segmentation.sas";
   %include "sas/05_logistic_regression.sas";
   ```

2. Set `%let outdir = ...;` at the top of `sas/99_export_golden.sas` to a writable
   directory, then run it:

   ```sas
   %include "sas/99_export_golden.sas";
   ```

3. Copy the four CSVs it writes into this directory:

   | File | Contents |
   |---|---|
   | `row_counts.csv` | `STAGE`, `N` for `home_equity`, `home_equity_final`, `home_equity_risk` |
   | `freq_loan_outcome.csv` | `LOAN_OUTCOME`, `FREQUENCY`, `PERCENT` |
   | `means_by_outcome.csv` | `LOAN_OUTCOME`, `LOAN_COUNT`, `LOAN_MEAN`, `LOAN_STDDEV`, `DEBTINC_COUNT`, `DEBTINC_MEAN`, `DEBTINC_STDDEV` |
   | `risk_segment_freq.csv` | `RISK_SEGMENT`, `FREQUENCY`, `PERCENT` |

4. Fill in the provenance block below and commit the CSVs together with it.

## When to regenerate

Whenever `data/home_equity.csv` changes or any program under `sas/` changes. Stale
golden files are worse than missing ones: the parity tests will pass against numbers
that no longer describe the SAS pipeline.
